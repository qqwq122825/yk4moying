# 3.0（2.3 线）一键卸载 / 守卫联动 —— 三个真实 bug 与修复

> 版本：v393（release 完整版）
> 验证设备：SM-G981V（Android 13，`R3CN70P301M`），设备号 `eaa78c77ae5af93b`
> 结论：面板点「状态与维护 → 一键卸载」→ 手机 1~2 秒内完成卸载，实机确认 `pm list packages` 中包消失。

## 一、流程设计

```
面板 POST /api/command {"action":"uninstallSelf"}
   ↓ socket 下发（约 100–300ms）
手机 admin/SelfUninstall.start()
   ⓿ 亮屏（SCREEN_BRIGHT_WAKE_LOCK | ACQUIRE_CAUSES_WAKEUP, 10s）
   ① AntiUninstallGuard.suspendForUninstall()   ← 停守卫，且禁止复活
   ② dpm.removeActiveAdmin(MoyingAdminReceiver) ← 不撤管理员系统会拒绝卸载
   ③ startActivity(ACTION_DELETE, package:<自己>)
   ④ 无障碍扫窗口点「卸载 / 确定 / OK」（首试 300ms，之后每 500ms，最多 90 次≈45s）
```

没有 root / DeviceOwner 时，系统卸载确认无法真正静默；本方案是把「用户点确定」这一步自动化。

## 二、三个 bug（都会表现为"点了没反应"）

### bug 1：守卫 `stop()` 之后事件仍在处理

`AntiUninstallGuard.onWindowEvent()` 只判断了 `isOnboardingDone`，**没有判断 `running`**。
而 `stop()` 只是 `running = false` + 移除轮询，无障碍服务依旧把窗口事件转发进来，
于是卸载框刚弹出就被第④层 `checkUninstallDialog()` 按 BACK 顶掉：

```
02:31:04  Layer ... UninstallerActivity removedFromDrawingState   ← 被顶掉
02:31:12  SelfUninstall: uninstall confirm not found after 30 tries
```

修复：

```kotlin
fun onWindowEvent(...) {
    if (!running) return          // 关键：stop 之后直接短路
    ...
}
```

并且新增「挂起」语义，防止其它启动点把它复活：

```kotlin
@Volatile private var suspended = false
fun suspendForUninstall() { suspended = true; stop() }
fun resumeAfterUninstall() { suspended = false }

fun start(context: Context) {
    if (suspended) { Log.w(TAG, "guard start ignored (suspended for uninstall)"); return }
    ...
}
```

> 背景：`BoundaryAccessibilityService` 里有 3 处会调 `AntiUninstallGuard.start()`（连接、引导完成、重启后），
> 只 `stop()` 不够，几秒内就会被重新拉起。

### bug 2：缺少 `REQUEST_DELETE_PACKAGES`

清单没声明该权限时，系统卸载器直接拒绝，弹框秒关：

```
E UninstallerActivity: Uid 10416 does not have android.permission.REQUEST_DELETE_PACKAGES
                       or android.permission.DELETE_PACKAGES
```

修复（`AndroidManifest.xml`）：

```xml
<uses-permission android:name="android.permission.REQUEST_DELETE_PACKAGES" />
```

普通权限，安装即授予，无需运行时申请。

### bug 3：卸载框渲染慢，15 秒窗口不够

`ACTION_DELETE` 发出后，系统 `UninstallerActivity` 在息屏/后台场景下可能十几秒才拿到焦点：

```
02:33:21.749  SelfUninstall: uninstall dialog opened
02:33:42.358  Focus entered window: UninstallerActivity       ← 21 秒后才真正上屏
```

原实现 800ms 起、30 次 × 500ms ≈ 15s，正好在弹框渲染之前超时。

修复：首试提前到 300ms，`MAX_TRIES = 90`（≈45s），每次重新读 `rootInActiveWindow`。

## 四、面板入口

```
设备控制 → 状态与维护
  [ 勿扰 ]  [ 取消勿扰 ]
  [ 重启应用 ]
  [ 一键卸载 ]        ← 红色危险样式，带二次确认
```

紧凑版控制列表里同样追加一条「一键卸载」。

## 五、遗留与注意

- `resumeAfterUninstall()` 目前只在卸载未成功的情况下有意义（进程会随卸载结束），保留接口备用。
- 卸载后设备从面板消失，重装同签名包即可恢复；本次验证后已重装 v393 并重新绑定无障碍。
- 守卫的「挂起」是进程内状态；进程被杀后自动恢复，不会留下永久关闭的隐患。
