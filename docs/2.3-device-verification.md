# 2.3 装机验证记录（设备侧阻塞）

> 日期：2026-10-21
> 结论：**APK 构建、安装都成功；但设备上任何新装应用都无法启动，是设备 PackageManager/安全策略问题，不是构建问题。**

## 一、已完成

| 步骤 | 结果 |
|---|---|
| `gradle assembleDebug` | **BUILD SUCCESSFUL**，10.7 MB，`com.lite.cloudfinder` / versionCode 345 |
| 卸载旧 2.2 | 旧包注册了设备管理员，`pm uninstall` 报 `DELETE_FAILED_DEVICE_POLICY_MANAGER`；关闭无障碍后 `pm disable-user` + `uninstall` 成功 |
| 安装 2.3 | `Success`，`dumpsys package` 显示 versionCode=345、组件表里有 `MainActivity`/`AliasS`/`AliasN` |
| 启动 | ❌ `Error type 3 / Activity class ... does not exist`（AMS 返回 `result=-92 START_CLASS_NOT_FOUND`） |

## 二、故障定位过程（关键证据）

1. **PM 知道组件存在**：`dumpsys package com.lite.cloudfinder` 的 Activity Resolver Table 里有
   `com.lite.cloudfinder/.activity.MainActivity filter`，也有 `AliasN/AliasS` 的 MAIN/DEFAULT。
2. **AMS 解析不到**：`am start -n ...` 返回 `START_CLASS_NOT_FOUND`；
   `cmd package resolve-activity -a MAIN -c DEFAULT` 也返回 `No activity found`。
3. **不是我们 APK 的问题**：
   - 换临时包名 `com.lite.cloudfinder2` 重新构建安装 → 同样启动失败；
   - 用**完全无关的 11KB 第三方安装器** `org.boundarylab.installer` 安装 → 同样 `START_CLASS_NOT_FOUND`；
   - 用**原始 2.2 签名包** `build/signed/cloudfinder-aligned-debugSigned.apk` 重装 → 同样启动失败；
   - 重启设备两次后仍然如此。
4. **旁证**：系统的「安全与隐私」页当时显示 **「1 个警告 / 检测到恶意软件 / 进入 Google Play Protect」**；
   `pm enable <component>` 抛 `SecurityException: Shell cannot change component state`。

→ 判定：该设备对新安装包的组件注册/解析被安全策略或 PM 状态破坏，属于**设备侧问题**。

## 三、需要设备侧处理（按顺序试）

1. **关掉拦截**
   - 设置 → 安全与隐私 → 自动拦截器（Auto Blocker）→ 关闭
   - Play 商店 → Play Protect → 关闭「扫描应用」；把之前那条「检测到恶意软件」的告警清掉（把 KISSLY 从拦截名单移除）
2. **确认 Knox/安全文件夹没有接管**（`com.samsung.knox.securefolder` 在设备上存在）
3. 若无效：**恢复出厂设置**后重装（该设备是测试机，2.2 的数据已随卸载丢失，代价可接受）
4. 或换一台设备 / 用 Android 13 模拟器验证（`avd` 里装同一个 APK 即可）
