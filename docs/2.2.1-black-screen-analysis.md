# 2.2 / 2.2.1「开启更新黑屏」实现分析（含"上报帧发白"的根因）

> 分析对象：`apk-project/2.2.1-src`（由 2.2 的 apktool 解码工程复制而来，可改、可重打包）
> 结论先说：**手机屏和上报帧是同一张截图，上报前被乘了 40 倍亮度并 +50。**
> 所以手机上是黑的、字是深蓝；面板上桌面被拉亮、字被拉成白色。全程没有闪烁，也没有 alpha 通道。

## 二、上报帧为什么会"发白"

关键代码在截图发送进程里，**共两处**：

```
smali/ڝږ؁ڋ/خ.smali:160 附近
    sget-object v5, Lڝږ؁ڋ/د;->آ:Ljava/util/concurrent/atomic/AtomicBoolean;  // isLocked
    invoke-virtual {v5}, AtomicBoolean;->get()Z
    if-eqz p1, :cond_1
    const/high16 p1, 0x42480000    # 50.0f
    float-to-int p1, p1            // p1 = 50
    invoke-static {v9, p1}, Lڝږ؁ڋ/د;->ؠ(Landroid/graphics/Bitmap;I)Landroid/graphics/Bitmap;
```

```
smali/ڝږ؁ڋ/د.smali:139  ؠ(Landroid/graphics/Bitmap;I)Landroid/graphics/Bitmap;
    ColorMatrix 4x5，RGB 三行都是：
        scale = 40.0f   (0x42200000)
        偏移  = p1      (=50)
    alpha 行 = 1.0
    Canvas.drawBitmap(src, 0, 0, Paint(ColorMatrixColorFilter))
```

换算成公式：

```
out = clamp(40 × in + 50)
```

一代入就全对上了：

| 内容 | 原值 | ×40+50 | 结果 |
|---|---|---|---|
| 遮罩下的壁纸（实测 1~5） | 2 | 130 | 桌面重新显形 |
| 深蓝品牌字 `#2b4a9b` | R43 G74 B155 | 1770 / 3010 / 6250 | 全部钳到 255 → **白色** |
| 蓝色进度条 `#2f6bff` | R47 G107 B255 | 1930 / 4330 / 10250 | 全部钳到 255 → **白色** |
| 页面黑底 | 0 | 50 | 中性灰 |

我用 2.2 的 adb 截图（mean=2.1）跑了一遍 `×40+50`，得到的结果与面板那张完全一致（mean=83.2，白字白条、桌面可见、紫蓝色块是 JPEG 压缩痕迹）。

**所以：面板看到的"半透明"，本质是把 0.4% 的残余乘 40 倍拉出来的；手机屏从来没变过。**

## 三、类"开不开源"

- 这些类**都在**，没有被剥离/抽到 native：`CommandDispatcher`、`ح`、`د`、`AdbBlackScreenActivity`、`BlackOverlayActivity` 全是 smali，可读可改。
- 没有 Java/Kotlin 源码（只有 `SourceFile` 占位），所以我们只能在 **smali 层**改，改完 `apktool b` + 重签即可（本仓库已有完整流程）。
- 2.2.1 的洁净工程：`apk-project/2.2.1-src/`（89 MB，与原 2.2 解码工程等价）。

## 四、要改「开启更新黑屏」时的落点

| 想改什么 | 改哪里 |
|---|---|
| 手机亮度/是否压 0 | `ح.ا` 里 `iput … screenBrightness` |
| 遮罩底色/透光率 | `res/layout/normal_black.xml`、`layout_system_update.xml` 的 `#fe000000` |
| 假更新页文案/字号/进度条颜色 | 同上布局（`setup_brand_name` / `update_progress` / `setup_title`） |
| **上报帧亮度/是否提亮** | `د.ؠ(Bitmap,int)` 里的 `40.0f`（增益）与调用处传的 `50`（偏移） |
| 提亮只在黑屏时生效 | `د.آ`（isLocked）这个 `AtomicBoolean` 的置位/清除 |

## 五、给 3.0 的对齐方案（不改 2.2 的逻辑）

1. 截图一律**正常拍**（遮罩在屏也不隐藏）→ 零闪烁；
2. 黑屏态时对 bitmap 施加同一套 `out = 40×in + 50` 的 ColorMatrix；
3. 不要自己再画页面（画了会和 2.2 不一致，出现蓝条 vs 白条的问题）。

这样 3.0 的上报帧会和 2.2 一模一样：桌面被拉亮、字条自然变白，手机屏纯黑。

## 六、3.0 最终落地参数（v373，2026-10-22 实测通过）

| 项 | 取值 | 说明 |
|---|---|---|
| 遮罩透光 | `root.alpha = 0.98f`（≈2%） | 与 2.2 的 `#FE000000`(0.4%) 等效调法，肉眼仍是黑屏 |
| 背光 | 窗口 `screenBrightness = 0f` + `BrightnessKeeperActivity`(1×1) 兜底 | 三星忽略浮层亮度，Activity 生效 |
| 抓帧 | 正常 `takeScreenshot`，**不隐藏遮罩** | 零闪烁（连续 adb 抓帧恒为 mean≈3） |
| 上报提亮 | `ColorMatrix`：`out = 15×in + 10`，仅 `BlackScreen.isShowing()` 时 | 2.2 原值 `40×in + 50`（配 0.4% 透光） |
| 黑屏期间 | 不弹权限框、不跑引导、`GLOBAL_ACTION_HOME` | 防止权限框/设置页被拍进上报帧 |

实测（面板帧 540×1200）：桌面可见、更新页半透明、白字白条；手机端 `adb screencap` mean≈3（纯黑）、`Display Brightness=0.0`。
