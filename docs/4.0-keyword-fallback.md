# 4.0 双保险：分步脚本 + 词表兜底

## 分派规则（`flow/VendorFlows.kt`）

| 机型 | 流程 | tag |
|---|---|---|
| MIUI（小米/Redmi/POCO） | `MiuiFlow`（Step1~6） | `Flow(MIUI)` |

| COLOROS / ORIGINOS / EMUI / 未知 | `KeywordFlow`（词表兜底） | `Flow(KEYWORD)` / `GenericEngine` |

## 词表来源

`assets/oem_pages.json`（约 480 KB）：从 Wonderly 1.8.19 的 `locateValues.json` 中只取
"开无障碍之后"用到的 56 组、10030 条词，另附 13 家厂商页面参数与 24 种系统文案。

关键分组：

```
权限   ALLOW_BUTTON_TEXTS / WHILE_USING_ALLOW_TEXTS / ALWAYS_ALLOW_TEXTS
管理员 DEVICE_ADMIN_KEYWORDS / DEVICE_ADMIN_DIALOG_KEYWORDS / ENABLE_BUTTON_TEXTS
通知   NOTIFICATION_KEYWORDS / ALLOW_NOTIFICATION_KEYWORDS
电池   BATTERY_KEYWORDS / NO_RESTRICTIONS_KEYWORDS
厂商   OPPO_*（5 组）/ VIVO_*（6 组）/ HUAWEI_APP_LAUNCH
自启   AUTO_START_KEYWORDS / BACKGROUND_KEYWORDS
```

## 兜底流程（`KeywordFlow` + `GenericEngine`）

每个阶段两件事：**用标准 Intent 打开页面** → **按词表点按钮**

```
permission    预算 40s，每 1.2s 一轮；权限页丢失会自动重新拉起
admin         预算 12s，每 1.8s 一轮
notification  预算 12s
battery       预算 12s（含 OPPO/VIVO 电池页）
→ 结束统一 OnboardingHooks.complete()（标记完成 / 收浮层 / 上报 / 起守卫）
```

安全阀：不点「取消 / 不允许 / 仅限这一次」（`isForbidden`）。

## 与防卸载的关系

`StartupCoordinator` 在跑流程前 `UninstallShield.stop()`，流程结束由
`OnboardingHooks.complete()` → `VendorGuard.start()` 重新起盾，
避免盾把引导要访问的设置页顶掉。
