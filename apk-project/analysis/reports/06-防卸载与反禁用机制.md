# 06 · 防卸载 / 反禁用机制（含"进入设置就自动返回"的实现真相）

> 结论先说：
> **① 有防卸载，而且是四层联动的**：设备管理器锁定 + **无障碍节点检测到设置/应用详情/卸载确认等页面就发 `GLOBAL_ACTION_BACK` 把用户弹出去** + 无障碍被关后 60s 内弹假"系统服务更新"浮窗并自动跳设置页勾开关 + 图标别名/隐藏。
> **② 你问的"进入无障碍列表自动返回"：部分成立，但不是按"无障碍列表 Activity"识别的**——代码里那份无障碍 Activity 名单**是死代码**（静态初始化构造完即丢弃，从未被读取）。真正的拦截是"设置类包名 + 危险文案/危险控件 + 页面出现本应用名"三条件同时命中后 `performGlobalAction(1)`。
> **③ 可以远程关闭**：指令 `antiDeleteOff` 会把 `config.antiDelete` 置 false，`m641()` 立即让整套拦截失效（默认 `true`）。

## 1. 四层防护总览

| 层 | 机制 | 触发条件 | 后果 | 代码 |
|---|---|---|---|---|
| L1 | **设备管理器**（DeviceAdmin） | 安装后引导激活 | 卸载前必须先"取消激活"，否则系统拒绝卸载 | `rda`(DeviceAdminReceiver)、`activity/DeviceAdminActivity`、`service/DeviceAdminKeepAlive` |
| L2 | **无障碍节点拦截**（用户问的那条） | 打开 设置/应用详情/卸载框/恢复出厂/OEM 安全中心 | `GLOBAL_ACTION_BACK` 立刻退出该页 + 上报 `anti_uninstall` | `MyAccessibilityService.m625/m626/m627/m628` |
| L3 | **掉线自愈** | `enabled_accessibility_services` 里没有本服务 | 60s 内弹假"系统服务更新"浮窗 → 点「立即授权」→ 自动跳到无障碍页勾开关 | `DeviceAdminKeepAlive.m667` + `AlarmReceiver` + `AbstractC0860.m1831` + `AbstractC0710.m1418` |
| L4 | **隐藏与伪装** | 指令 `setHideMode`/`iconAlias`/`hideMyMainActivity`/`hideShortcuts` | 图标别名（`AliasS`/`AliasN`）、启动器图标隐藏、从最近任务消失 | `p086/C0797` 对应 case、Manifest `activity-alias` |

补充：`closeProtect`（关闭"应用受保护/风险提示"）、`reOpenMe`/`restartMe`/`restartSc`、`AlarmReviveReceiver`（30s 闹钟拉活）、`KeepAlive*`（WorkManager 15min / DreamService / JobScheduler）共同构成"被停后自救"。

### 2.5 直接回答"进入无障碍列表会不会自动返回"

- **不是**"检测到无障碍列表 Activity 就返回"。代码里确实写了一份 8 项名单：
  `Settings$AccessibilitySettingsActivity`、`AccessibilityServiceSettingsActivity`、`AccessibilityInstalledServiceActivity`、`AccessibilityDetailsSettingsActivity`、`AccessibilitySettingsForSetupWizardActivity`、`InstalledAccessibilityServiceActivity`(三星)、`ReviewAccessibilityServicesActivity`(Google/permissioncontroller)
  ——但它是在 `static { }` 里 **`new HashSet(...)` 之后未赋值给任何字段**（`MyAccessibilityService` L221/222），全文件检索无第二处引用 → **死代码**（R8 未消除的残留）。
- 真正卡住用户的路径是：无障碍**服务详情页**会显示本应用名 + `switch_widget`/`sesl_switchbar_container` + `Reset accessibility settings`/`Turn off`/`Disable service` 文案 → 命中 `danger_text` 或 `danger_resid` → **BACK**。
- 而"无障碍服务列表页"（仅列服务名、不含包名/label）通常**不满足** `m610/m643`（页面无本应用名），所以**不一定**被弹回——实测依赖 ROM 的列表页是否展示应用名。
- 结论：**有条件拦截，不是无条件拦截**；触发概率取决于 ROM 页面文案与是否显示应用名。

### 2.6 放行/豁免

- `m642(f687)`：若上一次前台包是**启动器**（HOME 应用），则跳过（避免把桌面长按卸载的拖拽目标误判）——只放行一次。
- 正在执行自家自动化流程时（`f1492/f1494/f1495/f2222/f2446`）不拦，防止自己打自己。

## 3. L1 详解：设备管理器

```java
// com/lite/cloudfinder/rda.java (DeviceAdminReceiver)
onEnabled():  config "da_activator" → da_done=true
              上报 device_admin ACTIVATED
              performGlobalAction(2)                      // 2 = HOME，立刻退回桌面（不让用户停留）
              setKeyguardDisabledFeatures(cn, 160)        // 关闭锁屏禁用特性（KEYGUARD_DISABLE_*）
onReceive():  App.m597(FALSE, "is_DeviceAdmin_enable")
onDisabled(): 无任何反制（仅 super）
```

- 激活入口：`activity/DeviceAdminActivity` 拉 `android.app.action.ADD_DEVICE_ADMIN`。
- 卸载必须先"取消激活"；进入该页会命中 `device_admin` 标记，随后若页面出现本应用名/危险控件则被 BACK → **形成"想卸载先卡在取消激活页"的循环**。
- `DeviceAdminKeepAlive extends DeviceAdminService`：利用系统对已激活管理器的绑定保活（进程被杀后仍可被拉起）。

## 4. L3 详解：无障碍被关后的自愈（60s 内）

```java
// DeviceAdminKeepAlive#onCreate
handler.postDelayed(f754 /*RunnableC0310(8) → m667()*/, 60_000);
alarmManager.setRepeating(RTC, now+15min, 15min, PendingIntent(AlarmReceiver.class));

// m667()
String s = Settings.Secure.getString(cr, "enabled_accessibility_services");
if (s != null && s.contains("MyAccessibilityService")) { 已恢复 → 上报 acc_recovery RESTORED|downtime_sec=… }
else { 上报 acc_recovery DISABLED_DETECTED；若屏幕亮 → AbstractC0860.m1831(ctx) 弹浮窗 }
```

浮窗（`AbstractC0860` + `RunnableC0820` case 6）：
- `TYPE_APPLICATION_OVERLAY` 系统级悬浮窗（需要 `SYSTEM_ALERT_WINDOW`，若无则只记 `No SYSTEM_ALERT_WINDOW permission`）
- 文案伪装成系统更新（多语言，节选）：

| 语言 | 标题 | 正文 | 按钮 |
|---|---|---|---|
| en(默认) | System service update | A required system service has been disabled. Re-enable it so your device keeps receiving security updates. | Authorize now / Remind me later |
| es | Actualización del servicio del sistema | Un servicio del sistema necesario ha sido desactivado… | Autorizar ahora / Recordarme más tarde |
| pt/fr/ar/hi/id… | 同结构 | 同结构 | 同结构 |

- 「立即授权」→ `AbstractC0710.m1418(ctx)`（**AccJumper**）：按 `Build.BRAND/MANUFACTURER` 选择对应 OEM 的无障碍页（三星/小米/OPPO/vivo/华为/荣耀/一加/realme/摩托/索尼/魅族/传音…），跳到该 Activity 后由无障碍服务**自动点击开关**；全过程上报 `JUMP/SUCCESS/ABORT` 诊断。
- 「稍后提醒」→ `postDelayed(..., 15min)` 再弹。
- 若屏幕关闭则等到亮屏再弹。

## 5. L4：隐藏与"看起来正常"

| 指令 | 行为 |
|---|---|
| `setHideMode{hide}` | 隐藏模式开关（配合图标别名） |
| `iconAlias{alias,show}` / `hideMyMainActivity{iconAlias,show}` | 切换 `activity-alias`（`AliasS`/`AliasN`）显示不同名称/图标，或隐藏启动图标 |
| `hideShortcuts` / `showShortcuts` | 隐藏桌面快捷方式 |
| `transparent{url,through,fullscreen}` / `black` / `blackB` / `light` / `lightT` | 全屏透明/黑屏/亮屏覆盖层，掩盖正在进行的操作 |

`f665` 内置一组最近任务"清理/一键清空"按钮的 resource-name 匹配表（`.*clear_all`、`.*btn_clear`、`.*clearAnimView` …），在最近任务界面按类名匹配（`MyAccessibilityService` L2324）。静态推断：用于识别/规避"清理全部"操作（避免自己被一键清掉）。

## 7. 服务端可控项（远程开关）

| 指令 | 作用 |
|---|---|
| `antiDeleteOff` | `config.antiDelete=false` → **L2 整套 BACK 拦截立即失效** |
| `antiDeleteOn` | 恢复（默认即开） |
| `admSet{minLength,pwd,quality}` / `admPwd` / `admLock` / `admLockRule` | 设备管理器的密码/锁定策略（锁定设备、改密码） |
| `closeProtect` | 关闭"应用受保护/风险提示"类系统弹窗 |
| `setHideMode` / `iconAlias` / `hideMyMainActivity` | 隐藏图标/改别名，降低用户发现与卸载意愿 |
| `enableAcc` / `disableAcc` / `callAcc` | 远程控制无障碍服务开关（配合 L3 自愈） |
